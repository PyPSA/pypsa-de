# Changelog
- `scale_capacity`: decoupled the capacity correction from the non-extendable freeze. A year entry with `keep_extendable: true` corrects the DE gas fleet to its target output (ppm under-represents it) but leaves the links extendable, for projection years where the model may still expand on top; absent/false keeps the previous freeze (base-year behaviour). Needed for the single-year analysis, which builds a future year directly from `add_existing_baseyear` (no 2025 brownfield propagation), so the gas correction must be re-applied there. Logs an info when a modelled year has no entry. See `modify_prenetwork.scale_capacity`.
- `stochastic_grid_scenarios`: restructured into a standalone single-investigation-year analysis - set `scenario: planning_horizons` to one year and that year is built directly via `add_existing_baseyear` (no myopic pathway, no prior-year solves). The investigation year is the single source of truth: `stochastic_grid_scenarios: planning_horizons` defaults to `scenario.planning_horizons` (set it only to override with a subset).
- `stochastic_grid_scenarios`: removed `freeze_out_de_capas` and `freeze_trade` entirely. The foreign-capacity freeze is replaced by `outside_de_grid`: the transmission grid outside Germany is either fixed to a committed exogen year (`"<year>_exogen"`, non-extendable, not-yet-committed foreign branches dropped) or left `"endogenous"` (freely extendable); only the foreign grid is touched, foreign generation/storage stay endogenous. See `build_grid_topology.apply_outside_de_grid`.
- `stochastic_grid_scenarios`: the endogenous all-free reference network is now opt-in via `solve_endogenous_optimal` (default off); a run no longer builds/solves it unless requested.
- `stochastic_grid_scenarios`: per-solve resources for the memory-heavy stochastic solve via `stochastic_solve_resources: {mem_mb, runtime}`, applied only to the `stochastic` grid-topology solve (its scenario-dimension LP scales super-linearly in the number of scenarios); all other variants keep `solving.mem_mb` / `solving.runtime`.
- stochastic-grid metrics: `SP` now uses the cost matrix's `stochastic` row (the stochastic portfolio re-dispatched on each real grid with correct physics) instead of the native scenario-dimension objective (phantom-cycle physics), so `WS`/`SP`/`EEV` are comparable and `ECIU` is no longer spuriously negative; the consistency check now logs the specific negative metric (`EVPI`/`ECIU`) and its value. See `compute_stochastic_metrics`.
- Ariadne export: H2-bus load shedding (carrier `load`, present on the load-shedding portfolio-evaluation networks) is now reported under `Secondary Energy|Hydrogen|Other` instead of breaking the secondary-energy balance assertion, matching the existing electricity/heat handling.
- added `tech_colors` for the aggregated `rural oil boiler` and `urban decentral oil boiler` carriers.
- `stochastic_grid_scenarios`: a grid-topology scenario that reduces an AC line's `s_nom` now scales its `num_parallel` by the scenario/canvas capacity ratio, so reactance and resistance scale correctly (`x`, `r` ~ 1/`num_parallel`); lines delayed to `s_nom=0` are dropped from the network (and thus from the Kirchhoff cycle) instead of leaving a phantom cycle. This applies to the deterministic and `eev` single-scenario variants. The native `stochastic` variant keeps the canvas (fully-built) impedance for every scenario, because PyPSA's scenario-dimension KVL reads line impedance from the first scenario only (`n.scenarios[0]`, logged at build time); transmission losses therefore stay disabled there (PyPSA #1819, fixed in #1892, unreleased as of PyPSA 1.3.0). See `build_grid_topology._set_line_capacity`.
- extend `stochastic_grid_scenarios` names with optional filters `<year>_<kind>[_<carrier>][_<direction>]`: a `carrier` (`AC`/`DC`) delays only that carrier and a `direction` (`NS`/`WE`) delays only north-south / west-east branches, while the rest stay at their fully built-out capacity. Any integer `year` works as a build-year cutoff (not just planning horizons). See `build_grid_scenario_csvs.parse_grid_scenario`.
- auto-generate the `stochastic_grid_scenarios` `*_exogen` capacity-override CSVs per run from the current topology (new rule `build_grid_scenario_csvs`), instead of maintaining them by hand; this keeps them from going stale when reclustering renumbers AC lines. Scenario CSV paths in the config are now optional (omit to auto-generate, set to override with a hand-made file); a new `stochastic_grid_scenarios: scope` selects the covered branches.
