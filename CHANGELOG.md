# Changelog
- `stochastic_grid_scenarios` `freeze_trade`: the per-carrier DE gross-import caps now also apply to the ST portfolio-evaluation re-dispatch (`evaluate_grid_portfolio`), not only the LT grid-topology solves. The rule gained the `freeze_trade` param and the `freeze_trade_refs` input (same `_freeze_trade_ref_networks`, keyed on the evaluated `grid_scenario`, self-reference dropped), so a frozen portfolio re-dispatched on a realized grid faces the identical trade constraint the LT solve of that grid faced - without this, the ST runs could paper over a constrained grid by importing more, making the WS (LT) vs SP/EEV (ST) comparison inconsistent. No-op while `freeze_trade: false`. See `evaluate_grid_portfolio` / `additional_functionality.freeze_trade_imports`.
- Scenario-comparison PNG tables (`utils.df_to_png`): made the many-column ST tables legible - the `<portfolio>@<grid>` column labels now wrap onto three lines (`EXOG25` / `@` / `EXOG35`) with a taller header row, the figure width scales with the number of columns, and cell values are rounded by magnitude (no decimals >= 100, one decimal >= 10, two below) instead of a flat two decimals.
- System plots (`system_plots_grid_scenario`): (1) the per-region capacity maps (`plot_group_capacity_maps`, e.g. the Demand-Side Flex panels) now plot installed-capacity magnitudes (`abs`), so electricity-consuming links (electrolysis, chargers, power-to-heat) - signed negative by `optimal_capacity` at the AC bus - show as positive capacity with their cell values annotated, instead of being blank/negative; (2) fixed a double `/1e3` in the storage-energy maps (`plot_storage_map`) that labelled values `GWh` while they were actually `TWh` (e.g. PHS read ~0.04 instead of ~40 GWh); (3) H2 storage energy is now reported in `TWh` (large magnitude), in both `plot_storage_map` and the LT storage-energy diff maps, other storage stays `GWh`. See `system_plots` / `plot_grid_scenario_comparison`.
- LT grid-scenario comparison, capacity-diff maps: (1) plot installed-capacity magnitudes (`abs`) so electricity-consuming links (electrolysis, BEV chargers, power-to-heat) - which `optimal_capacity` signs negative at the AC bus - read as positive capacity, i.e. more capacity is a larger, not more-negative, number; (2) collapse the near-identical stochastic scenario slices (`topology-stochastic__{gs}`, one shared first-stage plan) into a single representative labelled `SP`, compared against each deterministic grid scenario (`SP_vs_EXOG25/30/35`) and `optimal`, instead of one `SP-EXOG{gs}_vs_EXOG{gs}` map per slice. See `plot_grid_scenario_comparison` / `system_plots.power_capacity_by_bus_carrier`.
- LT grid-scenario comparison: added an `outside_de_analysis/` subfolder (inside each LT `scenario_comparison/LT/...` output) with the rest-of-Europe (non-DE) aggregate - capacity comparison, all capacity tables and the generation/consumption tables - produced by inverting the existing DE region filter (`exclude=True`, everything whose bus is not DE, EU-shared commodity buses included). No maps or prices. The DE-filtered plotting functions (`get_capacities`, `make_capacity_tables`, `get_generation_consumption`, `make_generation_consumption_tables`) gained `region` / `exclude` parameters (defaults unchanged). See `plot_grid_scenario_comparison`.
- stochastic-grid metrics: additionally compute the `WS`/`SP`/`EEV`/`EVPI`/`ECIU` comparison for Germany only (`*_de` outputs). A whole-network LP objective is not decomposable per country, so the DE cost reuses `export_ariadne_variables`'s per-country accounting: `get_tsc` (capex + opex of DE-located assets, cross-border transmission split 50/50) plus the net trade cost (imports minus exports valued at domestic marginal prices). DE transmission capex is excluded to match the network-wide convention of treating the grid as exogenous, so the DE metrics isolate portfolio + dispatch + trade. All six tables (capacities, cost matrix, metrics, network-wide and DE) are now also rendered as PNGs (metrics bar chart, cost-matrix heatmap, capacities table), and the CSV + PNG outputs moved from the results root into `scenario_comparison/stochastic_metrics/` (dropped the `stochastic_grid_` filename prefix). Extracted `get_tsc` / `get_trade_cost` to module level in `export_ariadne_variables` for reuse. See `compute_stochastic_metrics`.
- `stochastic_grid_scenarios`: reintroduced the per-carrier trade freeze as `freeze_trade` (default `false`), now with a reference + margin instead of a hard cap. It is a `{carrier: "<ref><±margin>"}` mapping (carriers `AC`, `DC`, `H2`, `gas`, `renewable gas`, `renewable oil`, `methanol`, `oil`) that caps DE's annual gross import of each carrier at a solved reference network's import level times a margin factor: `"optimal"` (1.0x), `"optimal+10"` (1.10x), `"optimal-10"` (0.90x) or `"1.1optimal"`; the reference is `"optimal"` (the plain solved network) or a grid_scenario (its solved `topology-<scenario>` variant), always at the analysis year. The cap is a `<=` GlobalConstraint (DE may import less, not more) added to every grid-topology solve; a carrier whose reference is this very variant is skipped, so the stochastic solve waits for the referenced deterministic/optimal solve. Replaces the removed `freeze_trade` boolean/list. See `additional_functionality.freeze_trade_imports` / `parse_trade_spec`.
- `stochastic_grid_scenarios`: reintroduced a foreign-capacity freeze as `freeze_outside_de_capacities` (default `false`), complementary to `outside_de_grid`. It fixes foreign (non-DE) NON-grid capacities - generators, storage, stores and Links with `carrier != "DC"` (conversion, gas/H2 pipelines, distribution) - to a solved reference network, non-extendable, while leaving the foreign AC lines and DC links that `outside_de_grid` controls untouched. The reference is selectable: `"optimal"` (the plain solved network) or a grid_scenario name (that solved `topology-<scenario>` variant, e.g. `"2035_exogen"`), always at the analysis year. It is applied to every grid-topology variant except the source scenario itself (left unfrozen to define the capacities), so the stochastic solve waits for the chosen deterministic/optimal solve. Replaces the removed `freeze_out_de_capas`, now grid-aware. See `build_grid_topology.freeze_outside_de_capacities`.
- `scale_capacity`: restructured into a year-independent existing-fleet correction. The config is now a single `{region: {carrier: limit}}` block (previously keyed per year), applied only at the base year (`min(scenario.planning_horizons)`) where `add_existing_baseyear` installs the fleet it corrects. Freeze vs extendable is derived from the run: a myopic start year (`base < target`) freezes the corrected fleet non-extendable, a direct run (`base == target`, e.g. `[2030]`/`[2035]`/`[2040]`) leaves it extendable so the single-period model can expand on top. Later myopic brownfield years are left to the pathway instead of being re-clamped to a fixed target (which could shrink capacity the pathway built or re-inflate retired plants). The same config now works unchanged for both direct and myopic runs of any year. See `modify_prenetwork.scale_capacity`.
- `stochastic_grid_scenarios`: the direct-vs-myopic pathway is now selected purely via `scenario.planning_horizons` (with `foresight: myopic`): a single target year `[2035]` is optimised directly (standalone, from `add_existing_baseyear`, as before), while a multi-year pathway `[2025, 2030, 2035]` solves the myopic chain and brownfields the target off the solved prior year. The grid analysis targets only the final year, so `stochastic_grid_scenarios.planning_horizons` now defaults to `max(scenario.planning_horizons)` (previously the whole list); set an explicit subset to override. Added a `run_mode: opt_only` that builds and solves only the endogenous all-free reference network at the target year (forcing `solve_endogenous_optimal` on) with its ariadne export and system plots - no grid-topology variants, stochastic solve, ST runs, metrics or comparison plots - following whichever pathway `scenario.planning_horizons` selects.
- `stochastic_grid_scenarios`: the native stochastic grid solve now carries genuinely per-scenario line impedance and a per-scenario Kirchhoff voltage law. `build_grid_topology` scales each scenario slice's `num_parallel` (and so `x`/`r`) with its capacity (`_scale_scenario_line_capacity`), and `additional_functionality.add_scenario_kvl` replaces PyPSA's single scenario-invariant KVL with one cycle basis per scenario, built from that scenario's own reactances and with its `s_nom=0` corridors removed. This fixes the former "phantom cycle" (a not-yet-built corridor angle-locking its endpoints across all scenarios) and the first-scenario-only impedance (PyPSA's native scenario KVL reads `x` from `scenarios[0]` only). Requires a PyPSA with scenario-indexed optimization model builders (PyPSA/PyPSA#1951, unreleased as of PyPSA 1.3.0 - install from master): run the pipeline in the `grid-master` pixi environment (the default env stays on 1.3.0 and cannot run the stochastic variant; the `kvl` env is a minimal variant for the standalone methodology notebook). `transmission_losses` stays off for the scenario dimension pending PyPSA #1892.
- `scale_capacity`: decoupled the capacity correction from the non-extendable freeze. A year entry with `keep_extendable: true` corrects the DE gas fleet to its target output (ppm under-represents it) but leaves the links extendable, for projection years where the model may still expand on top; absent/false keeps the previous freeze (base-year behaviour). Needed for the single-year analysis, which builds a future year directly from `add_existing_baseyear` (no 2025 brownfield propagation), so the gas correction must be re-applied there. Logs an info when a modelled year has no entry. See `modify_prenetwork.scale_capacity`.
- `stochastic_grid_scenarios`: restructured into a standalone single-investigation-year analysis - set `scenario: planning_horizons` to one year and that year is built directly via `add_existing_baseyear` (no myopic pathway, no prior-year solves). The investigation year is the single source of truth: `stochastic_grid_scenarios: planning_horizons` defaults to `scenario.planning_horizons` (set it only to override with a subset).
- `stochastic_grid_scenarios`: removed `freeze_out_de_capas` and `freeze_trade` entirely. The foreign-capacity freeze is replaced by `outside_de_grid`: the transmission grid outside Germany is either fixed to a committed exogen year (`"<year>_exogen"`, non-extendable, not-yet-committed foreign branches dropped) or left `"endogenous"` (freely extendable); only the foreign grid is touched, foreign generation/storage stay endogenous. See `build_grid_topology.apply_outside_de_grid`.
- `stochastic_grid_scenarios`: the endogenous all-free reference network is now opt-in via `solve_endogenous_optimal` (default off); a run no longer builds/solves it unless requested.
- `stochastic_grid_scenarios`: per-solve resources for the memory-heavy stochastic solve via `stochastic_solve_resources: {mem_mb, runtime}`, applied only to the `stochastic` grid-topology solve (its scenario-dimension LP scales super-linearly in the number of scenarios); all other variants keep `solving.mem_mb` / `solving.runtime`.
- stochastic-grid metrics: `SP` now uses the cost matrix's `stochastic` row (the stochastic portfolio re-dispatched on each real grid with correct physics) instead of the native scenario-dimension objective (phantom-cycle physics), so `WS`/`SP`/`EEV` are comparable and `ECIU` is no longer spuriously negative; the consistency check now logs the specific negative metric (`EVPI`/`ECIU`) and its value. See `compute_stochastic_metrics`.
- Ariadne export: H2-bus load shedding (carrier `load`, present on the load-shedding portfolio-evaluation networks) is now reported under `Secondary Energy|Hydrogen|Other` instead of breaking the secondary-energy balance assertion, matching the existing electricity/heat handling.
- added `tech_colors` for the aggregated `rural oil boiler` and `urban decentral oil boiler` carriers.
- `stochastic_grid_scenarios`: a grid-topology scenario that reduces an AC line's `s_nom` now scales its `num_parallel` by the scenario/canvas capacity ratio, so reactance and resistance scale correctly (`x`, `r` ~ 1/`num_parallel`); lines delayed to `s_nom=0` are dropped from the network (and thus from the Kirchhoff cycle) instead of leaving a phantom cycle. This applies to the deterministic and `eev` single-scenario variants; the `stochastic` variant scales impedance per scenario slice instead (see the per-scenario KVL entry above). See `build_grid_topology._set_line_capacity`.
- extend `stochastic_grid_scenarios` names with optional filters `<year>_<kind>[_<carrier>][_<direction>]`: a `carrier` (`AC`/`DC`) delays only that carrier and a `direction` (`NS`/`WE`) delays only north-south / west-east branches, while the rest stay at their fully built-out capacity. Any integer `year` works as a build-year cutoff (not just planning horizons). See `build_grid_scenario_csvs.parse_grid_scenario`.
- auto-generate the `stochastic_grid_scenarios` `*_exogen` capacity-override CSVs per run from the current topology (new rule `build_grid_scenario_csvs`), instead of maintaining them by hand; this keeps them from going stale when reclustering renumbers AC lines. Scenario CSV paths in the config are now optional (omit to auto-generate, set to override with a hand-made file); a new `stochastic_grid_scenarios: scope` selects the covered branches.
